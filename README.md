# AMML Ranking Competition 2026

Это описание моего решения соревнования по ранжированию русскоязычных поисковых фрагментов. Здесь я собрала основные эксперименты: с чего начинала, какие модели пробовала, почему остановилась на ранговом ансамбле и что удалось проверить при подготовке к сдаче.

**Результат выбранной отправки:** Public NDCG@10 — **0.964651**, Private NDCG@10 — **0.967919**, **10-е место** в итоговой таблице. На соревнование был отправлен файл `submission_fusion_rank_mean.csv`, полученный в Kaggle-ноутбуке `notebookdcc3eaf112` (версия `Rank_Fusion`).

## 1. Данные и постановка задачи

Для каждого запроса нужно упорядочить предоставленные фрагменты так, чтобы релевантные оказались выше. В обучающей части 31 530 пар «запрос — фрагмент» для 3 042 запросов, в тестовой — 13 507 пар для 1 305 запросов. Метрика — средний по запросам NDCG@10. При совпадении скоров кандидаты сортируются по `id` как по строке.

Для меня было важно не потерять кандидатов при обработке данных: модель может менять их порядок, но итоговый `submission.csv` должен содержать все исходные тестовые `id`. В финальном коде это проверяется перед сохранением предсказаний.

При подготовке текстов я использовала нормализацию Unicode, удаление лишних пробелов и некоторых HTML-артефактов. Часть пустых заголовков удавалось восстановить по `article_id`, если этому идентификатору однозначно соответствовал непустой заголовок. Для слишком длинных фрагментов применялись разные способы отбора контекста. Это оказалось важно при ограниченной длине входа у моделей.

**Обучающие данные:** только размеченный `train.csv` соревнования. Для инициализации использованы публичные предобученные веса Qwen и Jina. Внешние размеченные корпуса для дообучения не использовались.

## 2. Валидация

Я разделяла данные **по `query_id`**, а не по строкам, иначе фрагменты одного запроса могли бы попасть и в обучение, и в проверку. Использовался `GroupShuffleSplit` с долей валидации 15%.

- В Qwen-ветке использовался seed `2028`.
- В Jina-ветке использовался seed `731`. Её валидационная часть содержала 457 запросов.
- Два разбиения не совпадали. Для совместного сравнения Qwen и Jina оставалось **79 общих запросов**; для отдельных сравнений способов объединения Jina использовались **378 других запросов**.

79 запросов — небольшая выборка. К тому же по мере работы я многократно смотрела на одни и те же локальные результаты. Поэтому небольшие различия NDCG нельзя считать надёжным доказательством улучшения на новых данных. Public Leaderboard тоже использовался для сравнения отправок, что создаёт риск переобучения при выборе метода.

## 3. Как развивалось решение

Сначала я получила Public Score **0.929890**. Затем пробовала менять обработку текстов, обучение и способы объединения предсказаний. Результат рос не на каждом шаге: например, отдельные версии Jina оказались слабее первоначальной Jina на её локальной валидации, а Median Fusion не улучшила Public Score по сравнению с уже имевшимся ансамблем.

Позже я дообучила Qwen3-Reranker-4B и Qwen3-Reranker-8B, затем отдельно попробовала Jina Reranker v2. Наиболее полезным оказался не выбор одной модели, а объединение моделей разных семейств. В конце я сравнивала способы соединения их скоров и рангов.

| Эксперимент | Public NDCG@10 | Что проверялось |
|---|---:|---|
| Первая отправка | 0.929890 | исходное решение |
| v2, лучший blend | 0.932972 | объединение предсказаний |
| v4 | 0.938300 | изменения нейросетевого пайплайна |
| Qwen v5 | 0.946017 | обученные Qwen3-4B и Qwen3-8B |
| Qwen v6 | 0.947637 | другой инференс и контекст для уже обученных адаптеров |
| Jina + Qwen | 0.955450 | объединение разных архитектур |
| Equal CPU | 0.960210 | обычный ансамбль Qwen и Jina |
| Equal GPU | 0.961307 | дополнительные варианты инференса Jina |
| Median Fusion | 0.957796 | медиана вместо среднего |
| RRF | 0.963501 | Reciprocal Rank Fusion |
| Hybrid Rank + RRF | 0.964150 | комбинация Rank Mean и RRF |
| **Rank Mean** | **0.964651** | **выбранная финальная отправка** |

Это именно результаты **Public Leaderboard**, а не значения на независимом наборе. Итоговый Private Score выбранной Rank Mean-отправки составил **0.967919**.

## 4. Какие модели вошли в финальный ансамбль

### Qwen3-Reranker-4B и Qwen3-Reranker-8B

Обе модели дообучались с помощью QLoRA: 4-битная NF4-квантизация, `r=16`, `alpha=32`, dropout `0.05`. В функции потерь сочетались бинарная классификация и попарное сравнение релевантных/нерелевантных фрагментов. Для инференса сохранялось состояние с лучшей локальной валидацией.

| Параметр | Qwen3-4B | Qwen3-8B |
|---|---:|---:|
| Seed | 5301 | 5302 |
| Learning rate | `3e-5` | `4e-5` |
| Максимальная длина | 640 | 512 |
| Batch / gradient accumulation | 4 / 4 | 2 / 8 |
| Фактически обработано микробатчей | 7 733 | 7 808 |
| Успешных обновлений | 1 933 | 975 |
| Лучший Validation NDCG@10 | 0.939141 | 0.932760 |
| Лучшая точка, микробатч | 5 156 | 2 608 |

Коммиты исходных предобученных моделей из логов: `22e683669bc0f0bd69640a1354a6d0aebcfeede5` (4B) и `77d193c791ed757ca307ee72715aa132723da912` (8B).

В **v6 новые шаги обучения Qwen не выполнялись**: использовались сохранённые после v5 адаптеры, но менялись формирование текста и инференс. В итоговой Qwen-ветке сохранена схема v6 с весами `0.75` для базовой комбинации v5 и `0.25` для дополнительного представления 4B (с нормализацией внутри запросов, как в исходном коде).

### Jina Reranker v2

Основой стала `jinaai/jina-reranker-v2-base-multilingual` (коммит `9cfeff2df7d40d1b78e75e5e9cebec92a99813c9`). В отличие от обучения на отдельных парах, здесь я использовала группы кандидатов целиком и функцию потерь с BCE, попарной частью и listwise-компонентой.

| Вариант | Особенности | Validation NDCG@10 |
|---|---|---:|
| Original | seed `7311`, LR `2e-5`, maxlen 288, 2 586 обновлений | 0.949417 |
| Jina A | продолжение Original, seed `9411`, LR `6e-6`, maxlen 384, 4 877 обновлений | 0.945153 |
| Jina B | отдельное обучение от исходных весов, seed `9412`, LR `1.7e-5`, maxlen 320, 2 586 обновлений | 0.943209 |

Jina A завершила второй проход не полностью: лучшая контрольная точка получена после 2 293 запросов второго прохода. Это фактический результат успешного запуска, а не запланированное число шагов.

Позднее добавились ещё два **варианта инференса без нового обучения**: `body` (фрагмент без заголовка, maxlen 384) и `long` (более длинный контекст, maxlen 512, веса Jina B). Таким образом, в финальном ансамбле пять выходов Jina: `old`, `a`, `b`, `body`, `long`.

Отдельно я проверяла модель для выделения ответа (QA), но она показала значительно более слабое качество на валидации, и в финальный ансамбль не вошла. Поэтому повторно обучать QA для получения финального результата не требуется.

## 5. Почему я выбрала Rank Mean

У Qwen и Jina разные масштабы выходных значений. При этом для NDCG@10 важнее всего, **какой документ оказался выше внутри конкретного запроса**, а не абсолютное значение логита. Поэтому я решила сравнить не только сложение нормализованных скоров, но и объединение позиций документов.

Финальная схема устроена так:

1. Получить нормализованный внутри каждого запроса скор ветки Qwen v6.
2. Для каждого из пяти выходов Jina нормализовать скоры внутри запроса, отсортировать кандидатов и получить ранги (при равных значениях — усреднённый ранг).
3. Преобразовать отрицательные ранги обратно в нормализованные внутри запроса оценки; усреднить результаты пяти Jina.
4. Сложить Qwen и Jina с фиксированными весами **0.5 / 0.5**.

Эта схема соответствует выбранной финальной отправке. Она отличается от RRF: в RRF у каждого ранга вес вида `1 / (k + rank)`, а в Rank Mean используется усреднение нормализованных рангов.

При сравнении выяснилось, что Hybrid Rank + RRF дал **0.964150**, RRF — **0.963501**, а Rank Mean — **0.964651** на Public. Поэтому для финальной отправки я оставила Rank Mean.

## 6. Ablation Study и доверительные интервалы

Чтобы понять, действительно ли новые варианты дают улучшение, я сравнивала методы на одних и тех же запросах. Получились такие локальные значения:

| Метод | 378 запросов Jina | 79 общих запросов Qwen + Jina |
|---|---:|---:|
| Equal GPU | 0.947832 | 0.944766 |
| Median Fusion | **0.953294** | 0.949430 |
| RRF | 0.951944 | 0.951323 |
| Rank Mean | 0.948972 | **0.955617** |

Здесь есть интересный момент: **Median Fusion лучше на 378 запросах Jina, но на Public её результат хуже**. Это стало ещё одной причиной не доверять только одной валидационной цифре.

Для анализа неопределённости использовался **paired bootstrap по запросам**, 20 000 повторений. У некоторых отличий доверительные интервалы пересекали ноль. Кроме того, сравнивалось много вариантов, поэтому без поправки на множественные проверки нельзя утверждать, что небольшие улучшения статистически значимы. Данные эксперименты — полезная диагностика, но не независимое подтверждение качества.

## 7. Как запустить финальное решение

Репозиторий содержит **ровно три файла** в корне: `solution.ipynb`, `requirements.txt`, `README.md`. История промежуточных экспериментов описана выше, в ноутбуке оставлен только финальный набор обучаемых моделей и обязательные этапы их инференса.

Исходная среда результатов: **Kaggle Linux (x86_64), Python 3.13, NVIDIA Tesla T4 × 2**, PyTorch `2.11.0+cu130`. Для самостоятельного повторения нужен Linux с совместимым CUDA GPU (желательно 16 ГБ или больше), установленными пакетами из `requirements.txt`, подключением к интернету для исходных предобученных весов Qwen/Jina и разрешёнными CSV соревнования. Данные сторонних обучающих корпусов не используются.

**Один запуск без ручного переключения:** положить `train.csv`, `test.csv` и `sample_submission.csv` в каталог `data/` рядом с ноутбуком; для другого расположения данных задать `AMML_DATA_DIR` либо `DATA_DIR` в первой кодовой ячейке. Установить зависимости `pip install -r requirements.txt` в то же Python-окружение, затем выполнить **Run All**. Все 13 технических стадий (`check_data`, обучение Qwen, обучение Jina, варианты инференса и финальный Rank Mean) запускаются автоматически в правильном порядке. Успешные этапы сохраняются в `.amml_work/amml_repro_cache/`, а итоговый файл будет находиться в `.amml_work/submission.csv` (на Kaggle — в `/kaggle/working/submission.csv`). При повторном запуске завершённые этапы пропускаются; вручную менять `STAGE` не нужно.

Полное обучение занимает много часов; **автоматизация не сокращает длительность работы моделей**. Из-за ограничений по CUDA и памяти другая конфигурация GPU может потребовать изменений или привести к ошибке. **Полный сквозной GPU-прогон этой объединённой версии ноутбука не проводился.** Подтверждённый результат соревнования Public `0.964651` / Private `0.967919` относится к исходным успешным экспериментальным ноутбукам; совпадение с повторным запуском в иной среде пока не подтверждено.
